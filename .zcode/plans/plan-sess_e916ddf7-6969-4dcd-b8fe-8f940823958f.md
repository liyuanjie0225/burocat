# R2 拟宠化行为引擎 — 开发方案（v5.2「数字工位同事」）

## Context

v5.1.x 已打通 ZCode hooks → 进度 pill + 完成通知，但形态是文字状态条。本次把 agent 状态**具身化演出**：agent 干活→猫在迷你键盘上敲击（气泡显示工具名）、**等确认→停手抬头看你（重点强化）**、**完成→撒花庆祝（重点强化）**、中断→叹气、长命令静默→打哈欠、睡着被 agent 吵醒→起床气。全部复用现有引擎资产（敲击管线/表情弹簧/起床气/粒子系统），后端几乎零改动。

探索结论（设计依据）：6 种 hook 事件已全部接好（start/tool/permission/done/info/interrupt），快照 `kuro-agent-status` 已含 waiting/tool/lastDone/interrupted；隐私捂眼与「用户真实键鼠优先」在引擎里已有现成门控（`privacyMode`/`isTypingRecently`）；2D 3D 双引擎独立持有行为状态，须双实现（默认渲染模式就是 3D）。唯一后端缺口：AgentTask 没有记「最近工具名」字段。

## 第 0 步：切开发模式（回答你的问题——必须做）

1. 托盘退出正式版 KuroCat.app（**关键**：正式版占着 27422 端口，dev 实例绑定失败会静默降级，事件全喂给正式版）
2. 仓库根目录 `npm run tauri:dev`——dev 启动自动把 `~/.zcode/cli/config.json` 的 hook 指向 `target/debug/KuroCat`（`current_exe()` 动态路径），**dev 模式 hook 事件完全可用**；前端热更新，Rust 改动自动重编译
3. 注意：dev 期间别开「开机自启」；正式版下次启动自愈 hook 路径
4. 调试利器：写一个 curl 演示脚本直接 POST `127.0.0.1:27422/agent-event`，不依赖真 ZCode 会话即可模拟完整生命周期

## 架构：三层分工

```
快照 kuro-agent-status（既有）+ kuro-input（既有）
  → src/embodiment.ts（新，纯逻辑状态机：相位推导、节流、用户优先门控）
    → 引擎演出 API（新增，2D/3D 镜像实现）：
       setAgentWorking(active, toolLabel)   敲击演出持续态
       setAgentWaiting(active, tool)        抬头看用户
       triggerAgentDone(interrupted)        撒花庆祝 / 叹气变体
       triggerAgentYawn()                   打哈欠
```

## 文件改动清单

**新建 `src/embodiment.ts`**（~230 行）——状态机：
- 自订阅 `kuro-agent-status` + `kuro-input`（复用 `agentStatus.ts:238` 的订阅先例）；复用已导出的 `activeAgentTasks()`
- 相位转换：任务出现/`tools` 递增→working；`waiting` 新出现→waiting；`lastDone`→done(interrupted?)；清除后回 working/idle
- 节流（PRD 3.2.7）：同相位演出触发 ≥500ms 合并；敲击 burst 上限 4；多任务只演 `lastEventMs` 最近的那个
- 静默 90s → `triggerAgentYawn()`（每段静默只一次，下个 tool 事件重置）
- 睡着时开工 → 先起床气（`wasSleeping()` 回调查询）→ 延迟 ~2.2s 进 working
- 本地 answered 启发式副本（~6 行）：waiting 后用户按任意键 ≥1s → 视为已答复 → 猫收回目光恢复 working
- 用户优先门控：`lastRealKeyAt` 650ms 内 → 跳过庆祝/哈欠演出（pill/toast 照常，PRD 3.2.6）
- 隐私门控：`isPrivacyActive()` → 一切演出暂停

**`src/catEngine.ts`**（2D，+~250 行）：
- 从 `onKeyDown`（1131-1336）抽出共享的按键视觉管线为私有 `pressKeyVisual(spec, now)`（keyAnims 按压/爪击编排/弹簧 kick/尾巴路径），真实键与 agent 键共用
- `setAgentWorking`：update() 内以 700–1800ms 随机间隔自发敲击；**不写** `lastAnyKeyAt/lastInputAt`（保持用户优先判定纯净），用显式 `agentWorking` 姿态值给 hunch/sway；敲击期间抑制逐键气泡，每 ~2.5s 用 `agentToolLabel`（工具名）出一次气泡（复用 `spawnBubble(label,…)`）
- `setAgentWaiting`：注视计算段（2124-2155）加分支——`targetGazeY` 向上、优先级 隐私>waiting>好奇；入场一次 `⏸ {tool}` 气泡
- `triggerAgentDone(false)`：`curiousUntil=now+900`（开心大瞳）+ `squashSpring.kick(2.1)` + `deskHopSpring.kick` + **confetti**：粒子系统 `CatFxParticle` 加 `'confetti'` kind（28 粒彩纸，vx±60、vy 上抛、重力+旋转、~1.6s 生命，`drawCatAliveFx` 绘制）；`(true)` 叹气：眯眼脉冲+耳朵耷拉+头低下，~1.2s
- `triggerAgentYawn()`：`IdleFidget` kinds 加 `'yawn'`（~1.6s），强制直触发绕过随机调度；眼睛挤压+张嘴+伸懒腰
- 新增 `getSleepStatus()`（2D 缺失，镜像 3D 的 1690-1697）
- 全部新入口 `!privacyMode` 早退，遵循既有门控模式

**`src/catEngine3d.ts`**（3D，+~200 行）：镜像同一套 API——敲击复用 `onKeyDown` 主体（1766-1816）去 wake/annoy、`desk.setKeyDown` + `spawnKeyPopup` 工具名；waiting 在 lookCursor 分支前加 `targetPitch=-0.10`；confetti 走 `spawnFx` + 预生成 4 色纹理；yawn 扩展 `IdleAct3D` kinds

**`src/main.ts`**：AppSettings 镜像加 `agentEmbodimentEnabled`；`initAgentStatus` 块后接 `initEmbodiment({...})`，闭包扇出到双引擎（沿用 `onAttention` 1140-1143 的双引擎模式）；`wasSleeping` 查当前活跃引擎

**`src-tauri/src/agent_status.rs`**（+~15 行）：`AgentTask` 加 `last_tool: String`（camelCase `lastTool`，tool 事件时记录，≤60 清洗）——working 气泡显示真实工具名
**`src-tauri/src/config.rs`**（+~15 行）：`agent_embodiment_enabled`，`#[serde(default)]` 默认 true；加 legacy 继承测试（镜像 564-569 模式）。注意 `isEnabled = agentStatusEnabled && agentEmbodimentEnabled`，天然继承 legacy 用户的状态开关，无需迁移

**菜单+i18n**：`menu.html` 在 183-195 区加「AI 拟宠化演出」开关行（跟随主开关显隐）；`menuMain.ts` handler/syncUI（镜像 688-698）；`locales/*.json` 5 语言补 3 个 agent 菜单项的 key（顺带把现有两个硬编码中文行也 i18n 化，对齐 commit 3279a8a 的零中文泄漏标准）

## 仲裁规则（写死在实现里）

优先级从高到低：① 密码防偷窥（捂眼时演出与 pet_* 全暂停）② 用户真实键鼠（650ms 内有真实输入 → agent 敲击自动让位、庆祝/哈欠跳过）③ agent 演出 ④ idle。用户敲键期间 agent 演出降级为仅更新 pill——陪伴用户永远是第一职责。
